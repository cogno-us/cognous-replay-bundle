# Changelog

## Unreleased

- Lifecycle contract conformance: attempt transitions and schema checks (execution-attempt-lifecycle re-vendored from ODES `e5fe3822`, label unchanged `0.1.0-draft`; no change to the pinned revision tuple, the profile labels or the import of any valid input; the normalised reconstruction output of every retained fixture is byte-identical). Executor attempt events and Control Plane attempt rows follow the contract's attempt state machines (`attempt_transition`: a closed attempt is never reopened, no `failed` after `acknowledged`), the rows of one Control Plane attempt keep one effect and decision (`attempt_identity_changed`), a result whose status claims an attempt names an attempt the export carries (`result_attempt_unresolved`), the result and its observation name the attempt's effect and decision (`result_binding_mismatch`), the producer status matrix is checked explicitly (`result_state_matrix`), text that is not valid Unicode is refused anywhere in an input (`schema_violation`), and the extension-name and digest patterns match the whole string. Refusals that carried no code now carry the contract's. Not enforced and recorded as strict-xfail probes: the implied-reasons floor of a completed journal check (`reasons_minimum`) and the closed set of additional check reasons. See `docs/contract-conformance-execution-attempt-lifecycle.md`.

- Journal observation content without an executor export (input validation, no contract change): when a proposal is supplied and no executor export is, a journal observation's `destination_state` (`effect_id`, `grant_id`, `target`, `amount`, `unit`, `payload`) is compared to the operation the proposal and the decision's binding commit to, as it already was on the export path; a conflict is refused. The operation digest is not compared (it needs the executor's operation). Valid captures import with the same status (`reconstruction_partial`, finding B004). One hand-written test source carried a partial `destination_state` and now carries the full one.

- Merge records with one timestamp (follow-up, no contract change): equal timestamps carry no order, so a history is accepted when some order consistent with the timestamps follows the producer's rules (a fold chain listed in either row order, a cycle or a double fold among tied records still refused).

- Signature envelope and redaction scope (no contract change, all stays `0.1.0-draft`): a replay-bundle signature written by this version covers the inner bundle (including its embedded `signature_metadata`), `signed_bundle_id` and the `signature_metadata` fields other than the value, under a fixed prefix; an earlier bundle-only signature still verifies and is reported as `bundle_only` by `signature_coverage` and by a stderr note from `arb verify`, and `--require-bound-envelope` / `allow_unbound_envelope=False` refuses it. A file signed by this version is not accepted by an earlier version. `redact_replay_bundle` gains three options, all off by default: `redact_task`, `redact_scope`, `clear_signature_metadata` (CLI `--task`, `--scope`, `--drop-signature`); the defaults and their output are unchanged. The test that pinned the unauthenticated envelope now pins it for bundle-only signatures only.

- Strict instants (no contract change, all stays `0.1.0-draft`): every place Replay reads a time (observation and refusal rows, the Programme-2 profile rows, recovery inspection, the route-B `linearized_at`) uses one reader, `instants.parse_instant`: `YYYY-MM-DDThh:mm:ss[.f]` with `Z` or `+hh:mm`/`-hh:mm`, upper-case `T`, ASCII digits, one to six fraction digits, hour 00 to 23. A seventh fraction digit, a space separator, week or ordinal dates, compact forms, hour 24 and a naive time are refused (`timestamp_invalid` where a code applies). Every captured valid record already used the strict form.

- Merge records read in time order (no contract change, all stays `0.1.0-draft`): a folded operation is folded once (`merge_operation_already_folded`), a survivor must not already be folded by an earlier merged record (`merge_survivor_already_folded`, which also refuses a cycle), and a chain of folds in time order is accepted; a join's `merged_into` may name the survivor of the record that folded its operation or a later survivor along the chain (the producer follows later merges to the root). Rows with another outcome do not count as folds.

- Input bounds, round 2 (no contract change, all stays `0.1.0-draft`): the nesting-depth scan reads each input once (cost linear in its size; it was quadratic for long runs of escaped quotes); the text inside an executor `payload_json` and a retained `claim_json` is depth-checked before it is decoded and a too-deep text is refused (`input_too_deep` / corrupt claim) instead of raising; the journal-to-check matcher takes a free check without a search and counts its work against a fixed budget (`MAX_MATCH_WORK`), refusing a run past it with `input_too_large`. Valid input and results are unchanged.

- Route B (atomic local executor) post-commit failure exports now import (qualification F-24). A result `unknown` carrying a destination *recovery report* (`status` in `applied|partial|hold|unknown`, with `claim_state`, `retry_eligible: false`, optional `effect_id`/`operation_digest`, `reason`) is accepted when: the report has no undeclared members; `retry_eligible` is false; identity and digest, when present, match the envelope; `applied`/`partial` carry `claim_state`, `effect_id` and `operation_digest`; `hold`/`unknown` carry a `reason`; `observed_state` equals the report status for `applied`/`partial` and `unknown` otherwise; and the result stays `unknown` and unacknowledged. The report is retained as record type `executor_recovery_report` with finding M021 and is never read as a validated observation. Executor evidence may carry `failure_record_id` (attributable reference) and `failure_class` alongside a recovery report. The same report on an effect-free reconcile (result `observed`, no attempt, no acknowledgement, no new effect) is accepted too. Regressions: `tests/test_route_b_recovery_import.py` with three real captured exports (post-commit read failure, lost acknowledgement with reconciliation down, effect-free reconcile) plus a planted `hold` report.

Producer 2.0.0 imports now reject: repeated executor attempt or destination effect rows; executor attempt events that are missing, repeated, out of `event_id`/`created_at` order, not started by `attempted`, or whose terminal event differs from the execution result status; an execution result that denies a newly executed effect the producer acknowledged.
